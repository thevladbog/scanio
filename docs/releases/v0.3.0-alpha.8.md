# Scanio v0.3.0-alpha.8

This prerelease fixes incorrect command availability reported during the physical Windows feedback cycle.

## Fixed

- The header **Disconnect** action is disabled when Scanio starts without an active scanner.
- The action becomes available only after an actual scanner connection.
- It is disabled again after the connection ends.
- Connection-state events now refresh both the header label and the action availability.

The complete `not connected -> connected -> disconnected` command-state cycle is covered by a regression test.

## Included from earlier feedback builds

- Application shutdown is bounded to a two-second graceful-disconnect period if a serial driver hangs.
- COM disconnect initiates handle closure before waiting for a pending serial read.
- Notebook buttons and export selectors vertically center their values.
- Header layout, logo sizing, primary-action contrast, and active-navigation indication include the earlier physical-feedback fixes.

## Still not included

- Keyboard-wedge scanner capture is not implemented yet.
- The Windows build is unsigned and may trigger a SmartScreen warning.

## Verification requested

- Start Scanio without connecting a scanner and confirm that the header **Disconnect** action is disabled.
- Connect a COM scanner and confirm that the action becomes enabled.
- Disconnect it and confirm that the action becomes disabled again.
